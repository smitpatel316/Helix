## (a) Ranked findings

### BLOCKERS

**B1 — No timeout or interrupt on any R evaluation; a hung R call strands the analysis forever.** `src/stats/webr.ts:29, :57–76, :78–99`; `src/native.ts:82–86`; `src-tauri/src/main.rs:557–570`. Any never-returning R computation (non-converging fit, stalled WASM fetch, wedged engine) leaves "Running…" forever with no cancel button, no elapsed time, and no working retry. WebR exposes `interrupt()` — Helix never calls it; no `AbortController` anywhere in `src/stats/` or the views. Only recovery is restarting the app. *Fix:* watchdog timeout around eval + wire `webR.interrupt()` / engine-window reload as recovery + a Cancel affordance. *Confidence:* confirmed. **Re-check after rebase** (all files upstream-touched).

**B2 — A hung install batch permanently poisons the install chain; every later package install hangs.** `src/stats/webr.ts:297–365, :367+`. The 120 s cap is only a per-caller `Promise.race`; the underlying batch promise is never cancelled and never settles, so `chain` never advances, `inflight` entries are never cleared, states stay `"loading"` forever, and every later `ensurePackages` call queues behind the dead chain and times out again — retry can never succeed even though the timeout message promises "Try again shortly". *Fix:* on timeout, evict the stuck batch from `inflight`, mark states `"failed"`, let `chain` advance (or rebuild the engine on timeout). *Confidence:* confirmed. **Re-check after rebase.**

**B3 — Enzyme-inhibition wizard cannot be completed with X + 1 Y series.** `src/views/analyses/wizards.ts:~826ff`. The `y` names question has `min: 2` (except Morrison) but with one Y series `options` has 1 entry, so `ready` is false forever and Next stays disabled with no message; only Cancel escapes. The runner *would* error clearly, but the wizard never lets you Run. *Fix:* skip/hide global models when `yNames.length < 2`, or ask the question with a message naming the shortfall. *Confidence:* confirmed. **Re-check after rebase.**

**B4 — Dose-response — Special wizard cannot be completed with X + 1 Y series.** Same shape as B3, `wizards.ts:~922ff` (`ys` min 2, 1 option). Runner has the clear error ("add at least a control and one shifted curve") but is unreachable. Same fix as B3. *Confidence:* confirmed. **Re-check after rebase.**

### MAJORS (ranked by user impact: silent wrong numbers first)

**M1 — Inhibitor concentration parsed from the FIRST number in the column title → silent wrong Ki/pA2.** `src/stats/xy/enzyme-inhibition.ts:44` (`parseInhibitorConcentration`); also consumed by `dose-response-special.ts` (Schild/EC50-shift B). A title like `Day 2 — 10 nM`, `Exp 1: 5 nM`, `Replicate 1 50 nM` parses as 2, 1, 1 instead of 10, 5, 50. Wrong-but-plausible [I]/B → wrong Ki, pA2, Kb, dose ratios, no warning. *Fix:* parse the LAST number (or the number adjacent to a unit), or require the wizard value when the title contains more than one number. *Confidence:* confirmed. Not upstream-touched.

**M2 — Binding association-then-dissociation: Kon start is Inf when median pre-Time0 time is 0.** `src/stats/xy/binding.ts:217`. Times like `[0, 12, 20, 30]` with Time0 = 10 give `log(2)/0 = Inf`, `pmax(Inf, 1e5) = Inf` → nls "port" gets a non-finite start and the fit fails outright on fittable data. (A tiny-but-nonzero median yields an astronomically large start, likely stalling the optimizer.) *Fix:* floor the median time (smallest positive pre-t0 time) or clamp the Kon start to a finite cap. *Confidence:* confirmed for the Inf start; exact nls error needs a runtime check. Not upstream-touched.

**M3 — One constant variable kills the whole correlation matrix.** `src/stats/multiple/correlation-matrix.ts:31,35`; `src/stats/xy/correlation.ts:70, :46–47`. All pairs go in one `evalNamedVector` call; `cor.test` errors on a zero-variance input, so the single error aborts the entire matrix — every pair fails, not just the constant variable's row/column. Same in x-vs-every-y mode. *Fix:* pre-check per pair (skip constant pairs to null cells, as the existing `MIN_PAIRS` skip does) or wrap each `cor.test` in R `tryCatch`. *Confidence:* confirmed (exact R error text needs a runtime check). **Re-check after rebase.**

**M4 — Shapiro–Wilk: one constant column (or n > 5000) fails the whole run.** `src/stats/column/shapiro-wilk.ts:10`. The R guard only covers `length(x) < 3` → NA; `shapiro.test` errors on identical values / n > 5000, the single batched eval throws, and `runAnalysis` returns a raw R error for all columns instead of per-column results. *Fix:* guard in the R wrapper (`length(unique(x)) < 2 || length(x) > 5000` → `c(NA,NA)`) and/or note the column. *Confidence:* confirmed (exact R error text needs a runtime check). **Re-check after rebase.**

**M5 — Dropped/invalid param values do NOT fall back to their default; most runners use `(params ?? DEFAULTS)` (whole-object only).** `src/lib/project-file.ts:424` × each runner. ## (b) Ideas — v1.1 candidates, figure builder, UX papercuts

### New v1.1 candidates (each checked against the existing backlog file — none duplicates it)
1. **Row means / totals** (SEEN) — per-row totals/means/medians/geometric means with SD/SEM/%CV/CI for XY and Grouped tables. The step Prism users do before almost every grouped figure; Helix has per-column descriptives only.
2. **Smooth, differentiate, or integrate a curve** (SEEN) — Savitzky–Golay smoothing, first/second numerical derivative, cumulative integral. Different math from the existing spline/Lowess fit (produces a new curve table). Daily analytical-lab work with no Helix path.
3. **User-defined equations for nonlinear regression** (SEEN) — user types their own equation with named parameters and initial values. The escape hatch that makes the curve fitter general; any lab with a nonstandard model is blocked without it.
4. **Extended descriptive statistics** (SEEN) — quartiles, %CV, skewness, kurtosis, geometric mean, sum per column. `describe()` returns only mean/SD/SEM/median/N (+CI/min/max/range). Quartiles/CV/skewness are what people check before choosing a test.
5. **Before-and-after plot style** (SEEN) — connect each subject's paired values with lines (optionally arrows) for Column/Grouped graphs. The standard paired-data figure; Prism's own paired-t-test how-to recommends it over bars.
6. **Right (second) Y axis** (SEEN) — plot a dataset on the right Y axis (max one). Two units/scales on one figure (dose + response, viability % + concentration) — extremely common in papers, currently impossible.
7. **User-facing log-scale axes** (SEEN) — Format Axes offers log X/Y on any graph. Today the only log axis in the codebase is hardcoded in the forest plot.
8. **QQ plot (normality) + residual plots for linear regression** (INFERRED — needs official-source verification before entering the backlog; the reviewer's web check surfaced only piracy-site mirrors, not a graphpad.com page). The visual normality check every stats checklist asks for.
9. **Compare slopes and intercepts of two or more regression lines** (INFERRED — same verification caveat; Prism's linear regression also offers a runs test for departure from linearity, could ride along). The standard "are these two slopes different?" question.
10. **Axis gridlines (major/minor) + tick controls** (SEEN) — Format panel has no gridline toggle anywhere; `plot-helpers.ts:430` explicitly notes "no internal gridlines". Journal figures often need light gridlines to read values off.
11. **One graph from multiple tables** (INFERRED — needs verification). Every graph node has a single `parentId`; overlaying a control curve from one experiment onto a treatment curve from another currently forces copying data into one table.

Deliberately NOT proposed: exclude/include cells, undo/redo, grid copy/paste, copy-graph-to-clipboard, regression CI band, ANOVA R² — all already exist; date X — already QAB-3; sort rows/columns — couldn't verify Prism even offers it.

### Multi-panel figure-builder design notes
Current state: **no layout/figure concept at all** — `NodeType = "table" | "analysis" | "graph"`; every graph has one `parentId` (one table); export is per-graph only; `.pzfx` layouts live in the opaque compressed `<Template>` blob, which the backlog already records as an import ceiling (users rebuild layouts in Helix; state that, don't silently drop).
What Prism's Layout sheets do that we must match: a layout is a **page** (fixed size/orientation), not a graph — multiple graphs placed as live, linked objects (edit the data and the layout updates); panels freely positioned/resized with snap/align/distribute (grids like 2×2, 1×3 are the common case, but Prism is freeform); **panel labels A, B, C…** auto-lettered in reading order — the single most visible journal requirement; text boxes, shapes/arrows, imported images/logos on the same page; **axis alignment across panels** is the hard part (panels sharing a Y axis need equal plot-area widths — Prism achieves this by matching graph sizes/positions, not shared axis objects); the whole layout exports/prints as **one figure** at journal DPI (makes backlog PDF/TIFF export doubly important).
Open design questions a builder needs answered first: (1) new `NodeType "layout"` as a top-level sidebar sheet, or a different sheet kind? (2) Live-linked panels vs snapshots — what happens when a graph's data changes or a graph is deleted? (3) Freeform absolute positioning vs a grid (rows × columns)? Mansi's figures are mostly grids — does freeform justify its complexity for v1? (4) Shared axes: automatic range sharing or purely visual alignment — who owns the range? (5) Panel labels: auto A/B/C in reading order with renumbering on rearrange? Global or per-panel label style? (6) Legends: each panel's own (Prism behavior) or one shared legend? (7) Drawing layer: full text/shapes/arrows/images for v1, or text boxes only? (8) Export: reuse the graph-export pipeline for the whole layout — which page sizes (single-column 89 mm, double-column 183 mm journal widths)? (9) Print: is the layout the printable unit, and does v1.0 need print at all? (10) Where does the builder live in the UI — its own workspace view like a graph, or a modal?

### UX papercuts (friction only — no wrong numbers, no crashes)
1. **No way to re-open an analysis's parameters** — the params selector only opens at creation; to change an option you delete the node and start over. Prism re-opens the parameters dialog from the results sheet. (Also: a failed analysis shows plain error text with no path back to the wizard — combined, a failed analysis forces delete-and-recreate.)
2. **No Copy-results button** — results view notes "everything is selectable" but there's no one-click copy of a results table; Prism users copy results into manuscripts/Excel constantly.
3. **Two titles per graph, unclear which is which** — toolbar/sidebar `node.name` vs the chart's drawn `options.title` in the Format panel; editing one never touches the other, nothing labels the distinction.
4. **Axes section is min/max/step/thickness only** — no log scale, gridlines, or tick control; a daily Prism user will look for these first and find nothing.
5. **"Import Prism File…" doesn't say .pzfx-only** — a user with a `.prism` file gets a picker that won't take it, with no explanation and no warning that the import drops analyses/graphs (only a post-import alert says so).
6. **Table menu duplicates itself** — "New Table…" plus all six table types as direct items.
7. **CmdOrCtrl+Backspace means two things** — clears selected cells in the grid, deletes the active sheet elsewhere; the menu label changes but the grid behavior isn't discoverable from it.
8. **"Exclude / Include" never shows state** — same label whether the selection is currently excluded or not.
9. **Export remembers the last folder only for the session** — reopening Helix forgets it.
10. **Analysis errors are a dead end** — failed analysis shows plain error text with no path back to the wizard (see #1).
